# Carp Strategy Execution

本文规定 Carp 的策略研究、实现和验收流程。处理策略、回测、baseline 或 commit 前必须阅读。

## 总原则

- commit `a8dd63a` 是永久保留的原始对照；Git tag `strategy-benchmark-20260907-stage1` 保存第一阶段基准，`strategy-benchmark-20260907-single-strategy` 保存当前单策略 baseline。后续研究不得恢复多家族、开关和例外路由。
- 先梳理源码、数据流、信号状态、成交和输出，再改完整影响面。
- 只修改真实受影响的文件，不增加任务未要求的参数、配置、脚本或抽象。
- 任何候选先检查 `docs/strategy-blacklist.md`；命中黑名单直接停止。
- 所有正式结论来自 `data/backtest_data/*_hfq.csv`，不使用临时下载或在线数据代替。

## 策略闭环

一个策略改动必须同时回答：

1. 什么历史信息在什么时点形成入场候选？
2. 信号何时确认，实际何时成交？
3. 持仓状态如何从一天传到下一天？
4. 正常退出和风险退出分别由什么触发？
5. 数据结束时未平仓权益如何计价？
6. 为什么规则能跨 A/H 股、科技、成长、医药、银行、白马和震荡样本解释？

答不完整时，不进入实现。

## 研究约束

- 不为单只股票或少数赢家设计规则。
- 不按股票代码、名单、行业名称或事后画像选择策略。
- 不把同一批股票同时用于反复选参数和证明泛化；`codes_250.txt` 是开发集，新增密封集只能在候选冻结后揭开。
- 规则数量和参数自由度共同构成策略复杂度；审计时同时统计策略家族、开关、状态和有效参数，不能只通过删函数宣称已经简化。
- 参数必须有市场结构含义并采用合理的粗粒度；不保留纯扫描得到的高精度魔法数字、狭窄区间或峰值/悬崖参数。
- 参数验收看邻域而不是最优点：冻结候选后至少比较相邻粗粒度参数，并要求 OLD128、NEW122 和密封集没有明显反向。没有稳定平台时，删除该参数化规则或选择更简单的默认值。
- 大幅删减策略与参数后，若主要指标总体持平或仅小幅、可解释地下降，而留出泛化、风险、集中度或可审计性改善，可以接受该取舍；不得为追回开发集小幅损失继续增加补丁。
- 买点和卖点分别做归因。买得好不能掩盖卖点过拟合，卖得好也不能掩盖入场选择失真。
- 先做 OLD128 / NEW122 分组对比，再看开发集 ALL250 和密封集。旧池显著好、新池或密封集反转时，优先判定为过拟合。
- 检查收益是否由少数极端赢家贡献，并同步观察 median、losers 和交易数。
- 不用算术平均收益单独验收策略；至少同时检查 10% 截尾均值、收益四分位、持有期年化中位数、亏损率和前五赢家贡献。

## 未来函数红线

任何关键指标大幅改善时，先假设存在未来函数、未来数据、数据泄漏或不现实成交，再验证策略解释。

重点排查：

- 负向 `shift`、居中 rolling、全历史极值、全样本归一化。
- 用未来才能确认的局部高低点、波浪段、趋势标签或股票画像。
- `bfill`、后向填充或把最终分类结果写回过去。
- 回测期间加载当前指数、当前成分、当前财务状态或其他非 as-of 数据。
- 把收盘后才知道的结果解释成可按已经过去的同一收盘价成交；当前 `close` 只能作为尾盘最后一分钟决策与成交的日线近似。

必须运行逐日前缀回放：

1. 用完整历史计算参照结果。
2. 遮住未来数据，从第一行开始一行一行放开。
3. 每个前缀只计算到当日。
4. 比较前缀最后一行与参照结果同一行。
5. 至少比较买点、卖点、持仓、止损、触发原因和所有关键中间状态。
6. 任意差异都按未来数据问题处理，要求 0 差异。

当前可用的标准命令：

```bash
python3 stock_trading_advisor/tests/test_lookahead_bias_smart.py
```

## 成交口径

- 假设日线第 `t` 日尾盘最后一分钟形成信号并成交，基线回测使用第 `t` 日 `close` 近似该时点价格。
- 信号不得读取第 `t+1` 日及其后的数据。
- 日线 `close` 不能证明分钟内信号先于成交成立；需要更精确成交验证时必须使用分钟级快照和成交数据。
- 遗留基线引擎在数据结束时强制平仓，且持仓期间的历史资金曲线没有逐日盯市；该缺陷必须明确披露。
- A 组必须保留上述历史语义以精确复现报告；B/C 组使用同一个修正的每日盯市引擎判断策略差异。
- 基线 `2.07` 按单笔收益率汇总；修正审计同时报告同公式 PF 和金额 PF，名称与公式不得混用。

## 验证顺序

1. 静态检查和编译。
2. 对少量 A/H 股运行离线 smoke report。
3. 运行策略前缀未来函数测试，要求 0 失败。
4. 从受保护 Git 引用隔离运行 `codes_250.txt` 复核原报告；不得为复现旧报告把旧策略拷回当前源码。
5. 冻结候选后从当前正式入口运行 DEV250、OLD128、NEW122、额外港股验证集和 ALL305。
6. 引擎有变化时完成 A/B/C，并同时检查百分比 PF、金额 PF和每日盯市回撤。
7. 搜索已删除策略、配置和 CLI 名称，确认没有旁路残留。

正式回测命令：

```bash
python3 stock_trading_advisor/main.py --report -b 000001 300750 00700
python3 stock_trading_advisor/main.py --report
```

## 验收指标

至少记录：

- `median`
- `10% trimmed mean` 和 `P25/P75`
- 持有期年化收益中位数
- 日等权策略袖套的 `CAGR / max_drawdown / Sharpe`
- 与基线同公式的收益率 `tPF`，以及单独标注的金额口径 PF
- `losers`
- `max_drawdown`
- 平均和总交易次数
- 前五赢家占全部正收益比例
- `avg_return`，仅作为观察右尾的辅助指标
- OLD128 与 NEW122 的分组变化
- 候选冻结后的密封验证集结果
- 未来函数逐日前缀差异数

非策略改动必须保持买卖点和回测结果一致。策略改动必须有跨股票池的净收益证据；大幅降低规则、参数和状态复杂度时，允许主要历史指标总体持平或有限退步，但必须量化代价，并确认留出泛化、参数稳定性、风险或可审计性确有改善。综合代价更大或副作用过大时完整回退，不留下关闭状态的代码或配置。

## Baseline 与提交

- baseline 必须注明股票数、数据复权、数据时间范围、成交口径和代码 commit。
- 报告文件、股票清单和质量快照必须能够互相对应。
- commit 前检查工作区，只纳入本任务文件，不覆盖用户已有改动。
- commit message 说明策略变化和正式回测核心指标，不使用单只股票结果代表整体。
- 未经用户明确要求，不自行 commit 或 push。

## 停止条件

出现以下任一情况必须停止保留候选：

- 逐日前缀测试出现任何差异。
- 需要股票特例、名单路由或黑名单方法才能成立。
- OLD128 提升而 NEW122 或密封验证集明显反转。
- 主要收益由极少数股票或极少数交易贡献。
- 成交价格无法在当时真实获得。
- 无法解释指标改善来自哪里。
