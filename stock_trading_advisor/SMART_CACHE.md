# 智能缓存策略文档

## 概述

项目现已实现**智能缓存策略**，根据运行模式（回测/实时）和交易时间自动选择最优的数据获取方式，既保证数据新鲜度，又最大化性能。

## 缓存策略

### 1. 回测模式（带 --backtest 或不加 --no-backtest）

#### 行为
- ✅ **优先使用缓存**：如果缓存存在，直接使用，不检查新鲜度
- ⚡ **性能优化**：避免重复网络请求
- 📊 **一致性保证**：多次回测使用相同数据集

#### 逻辑
```python
if is_backtest_mode and cache_exists:
    使用缓存数据  # 不管数据日期
```

#### 使用场景
- 策略回测
- 参数优化
- 历史分析

#### 示例
```bash
# 回测模式（默认）
python main.py -s 000001

# 日志输出
# 从缓存加载数据: /path/to/cache/000001_xxx.csv
# 回测模式: 缓存命中
```

---

### 2. 实时模式（--no-backtest）

实时模式会智能判断当前时间，采用不同策略。

#### 2.1 交易时间内

**A股交易时间**:
- 上午: 09:30 - 11:30
- 下午: 13:00 - 15:00

**港股交易时间**:
- 上午: 09:30 - 12:00
- 下午: 13:00 - 16:00

##### 行为
- 🔴 **总是获取最新数据**
- 💾 **更新缓存**
- 📡 **实时性优先**

##### 逻辑
```python
if is_trading_time(market):
    fetch_new_data()  # 强制获取最新数据
    update_cache()
```

##### 使用场景
- 盘中分析
- 实时监控
- 当日交易决策

##### 示例
```bash
# 交易时间内运行
python main.py -s 000001 --no-backtest

# 日志输出
# 交易时间内，获取最新数据
```

---

#### 2.2 非交易时间（盘前、盘后、周末）

##### 行为
- ✅ **检查缓存新鲜度**
- 🆕 **如果缓存包含最新交易日数据** → 使用缓存
- ⏬ **如果缓存过期** → 获取新数据并更新缓存

##### 逻辑
```python
if not is_trading_time(market):
    latest_trading_date = get_latest_trading_date(market)
    cache_last_date = get_cache_last_date()

    if cache_last_date >= latest_trading_date:
        use_cache()  # 缓存新鲜
    else:
        fetch_new_data()  # 缓存过期
        update_cache()
```

##### 新鲜度判断规则

| 当前时间 | 最新交易日 | 说明 |
|---------|----------|------|
| 周一早上8点 | 上周五 | 返回上周五 |
| 周一下午4点 | 今天（周一）| 已收盘，返回今天 |
| 周二早上9点 | 昨天（周一）| 未开盘，返回昨天 |
| 周六任意时间 | 上周五 | 周末返回周五 |
| 周日任意时间 | 上周五 | 周末返回周五 |

##### 示例场景

**场景1: 周五晚上10点**
```bash
python main.py -s 000001 --no-backtest

# 逻辑:
# 1. 判断: 非交易时间（盘后）
# 2. 最新交易日: 2025-10-17 (今天周五)
# 3. 缓存最后日期: 2025-10-17
# 4. 结论: 缓存新鲜 ✓
# 5. 使用缓存数据

# 日志输出:
# 非交易时间，使用新鲜缓存
# 从缓存加载最新数据 (最后日期: 2025-10-17)
```

**场景2: 周一早上8点**
```bash
python main.py -s 000001 --no-backtest

# 逻辑:
# 1. 判断: 非交易时间（盘前）
# 2. 最新交易日: 2025-10-13 (上周五)
# 3. 缓存最后日期: 2025-10-13
# 4. 结论: 缓存新鲜 ✓
# 5. 使用缓存数据
```

**场景3: 周一下午5点（缓存过期）**
```bash
python main.py -s 000001 --no-backtest

# 逻辑:
# 1. 判断: 非交易时间（盘后）
# 2. 最新交易日: 2025-10-14 (今天周一)
# 3. 缓存最后日期: 2025-10-13 (上周五)
# 4. 结论: 缓存过期 ✗
# 5. 获取最新数据并更新缓存

# 日志输出:
# 非交易时间，缓存不新鲜，获取最新数据
```

## 注意事项

### 1. 节假日处理

⚠️ **当前限制**: 系统简化处理，只判断周一至周五为交易日，**未处理节假日**。

**影响**:
- 节假日可能被误判为交易日
- 缓存可能在节假日被认为"过期"

**改进计划**:
- 集成节假日数据库
- 支持A股/港股节假日日历

### 2. 缓存清理

缓存文件会一直保留，建议定期清理：

```bash
# 清理所有缓存
rm -rf data/cache/*

# 清理特定股票缓存
rm data/cache/000001_*.csv

# 清理7天前的缓存
find data/cache -name "*.csv" -mtime +7 -delete
```

### 3. 数据一致性

**回测模式**:
- ✅ 优点: 多次运行结果一致
- ⚠️ 注意: 如需最新数据，请先删除缓存

**实时模式**:
- ✅ 优点: 自动更新最新数据
- ⚠️ 注意: 盘中频繁运行会多次请求网络

## 故障排查

### 问题1: 缓存总是过期

**现象**:
```
非交易时间，缓存不新鲜，获取最新数据
```

**可能原因**:
1. 缓存文件日期格式错误
2. 系统时间不正确
3. 节假日判断问题

**解决方案**:
```bash
# 检查系统时间
date

# 检查缓存数据最后日期
tail -1 data/cache/000001_*.csv

# 手动测试市场状态
python -c "from src.market_hours import MarketHours; print(MarketHours.get_market_status('CN-A'))"
```

### 问题2: 交易时间判断错误

**测试**:
```python
from src.market_hours import MarketHours
from datetime import datetime

print("当前时间:", datetime.now())

```

### 问题3: 回测模式仍然请求网络

**检查**:
```bash
# 查看日志，确认是否传递了 is_backtest_mode

```

**原因**:
- 可能是缓存文件不存在
- 第一次运行会请求网络并创建缓存
